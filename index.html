Abstract

The ability to generate new questions offers a way for AI systems to expand the challenges available for evaluation and learning. For visual questions, however, generating a correct answer is not enough: the answer may be known from the scene used to construct an image but not recoverable from the rendered pixels themselves. This makes automatic verification difficult, because checking only the underlying scene does not establish that the visual question is actually answerable. Using vision–language models to perform this check introduces a different problem: validity then depends on the capabilities of the models being evaluated. We introduce BlindLoop, a system in which coding agents propose visual questions and write two programs: one generates question instances and their expected answers, while the other solves them from the images alone. We check agreement across instances generated with different random seeds. We then investigate whether this approach supports continued growth of a question collection, whether agents can follow requests about which image regions their solving programs use, and whether they can use feedback about errors made by frontier models. We also analyze the verification procedure and evaluate the generated data through supervised fine-tuning. The resulting collections continue to grow across different question types, and agents usually follow requests about the size and shape of image regions used by their solving programs. Fine-tuning open-weight models on generated examples improves accuracy on held-out generated questions, with gains on several external benchmarks. Project page: https://theblindloop.github.io/

Motivation

An answer in the scene is not enough.

A generated image can hide or distort the evidence needed to answer its question. Knowing what the scene was supposed to contain does not establish what a reader can recover from its pixels.

Using a vision-language model to judge answerability ties validity to that model’s capabilities. BlindLoop instead asks coding agents to write two answer programs: one computes from the scene specification, and the other recovers the decision from the image alone.

The verifier checks their agreement on fresh instances. This provides a mechanical test of image-based answer recovery; human clarity and training value are evaluated separately.

Method

The answer must be recoverable from the pixels.

BlindLoop asks a coding agent—a model that writes and tests code—to create a reusable visual question and two programs that answer it from different inputs.

One world, many instances

A question world contains a sampler, a renderer, fixed question text, and two answer programs. The sampler draws a scene description; the renderer turns it into an image. An instance is one sampled scene and its rendered image.

Two inputs, the same decision

The scene specification describes the objects and their relationships. The forward program answers from this specification. The inverse program answers from the image alone.

def analytic_gold(scene: dict) -> str:
    linked = [i for i, panel in enumerate(scene["panels"]) if panel["linked"]]
    if len(linked) != 1:
        raise ValueError(f"scene has {len(linked)} interlocked panels, expected exactly 1")
    return f"panel-{linked[0] + 1}"

Original question

This image shows five framed square panels of identical size standing side by side in one row, numbered 1 to 5 from left to right. Every panel holds exactly two rings of the same thickness, drawn in two different flat colours, and in every panel the two rings cross each other at exactly two places, so ring count, ring size, colour, position and the amount of ink carry no information. The rings are opaque, so at each crossing one ring passes in front and hides a short piece of the other one, leaving a plain break in the ring behind. Two rings are interlocked when neither ring stays in front the whole way round: one ring passes in front at one crossing and behind at the other, so each of the two rings carries exactly one break and each is still a single connected curve. Two rings are merely stacked when the same ring passes in front at both crossings, so that front ring carries no break at all while the ring behind it is broken twice and falls into two separate pieces. Exactly one panel holds a pair of interlocked rings. In each of the other four panels the pair is merely stacked, and the piece of the ring behind that lies between its two breaks is at least 26 pixels long, so both of its breaks are plainly visible. Which ring is drawn in which colour, which ring is in front at a given crossing, and where the pair sits inside its panel are all free to vary. Which numbered panel holds the two interlocked rings, that is the panel in which each of the two rings carries exactly one break? Answer with exactly one of: panel-1, panel-2, panel-3, panel-4, panel-5.

How many checkpoints are inside the band?

Original forward code
def analytic_gold(scene: dict[str, Any]) -> str:
    """Return the visible count, using only the three rendered value arrays."""

    flags = [
        lower < value < upper
        for value, lower, upper in zip(
            scene["trace_values"], scene["lower_values"], scene["upper_values"]
        )
    ]
    if len(flags) != 6:
        raise ValueError("a scene must contain six checkpoints")
    return str(sum(flags))

Which dot is at the circle’s center?

centermarkers

Compare the marker coordinates with the specified circle center; select the closest.

Original forward code
def analytic_gold(scene: dict) -> str:
    """Select the marker nearest the declared circle center from visible fields."""

    cx, cy = scene["center"]
    markers = scene["markers"]
    winner = min(markers, key=lambda item: math.hypot(item["xy"][0] - cx, item["xy"][1] - cy))
    return str(winner["color"])

Reading the diagram

What each component does

The sampler and renderer create an instance. The forward and inverse programs answer the same question from different inputs. The verifier checks their agreement.

  1. 01

    Sampler

    Choose what to draw. The sampler uses a random seed to choose the objects and their properties. Its output is a scene specification: structured data describing one instance.

    In this example

    Choose six strings, their spacing, and the guitar’s position.

    Random seed→Scene specification
  2. 02

    Renderer

    Draw the chosen scene. The renderer turns the scene specification into an image. This makes the chosen properties visible as pixels.

    In this example

    Draw the guitar with six strings crossing a pale bridge.

    Scene specification→Image
  3. 03

    Forward program

    Answer using the scene data. The forward program computes the decision from the scene specification. Here that is a lookup; other questions may require geometry, connectivity, or simulation.

    In this example

    Read string_count = 6. No pixel measurements are needed.

    Scene specification→Decision: 6
  4. 04

    Inverse program

    Answer using only the image. The inverse program recovers the decision from visible pixels. It can know the world’s visual conventions, but does not receive this instance’s scene specification.

    In this example

    Locate the pale bridge, count six dark runs, and check that three neighboring rows agree.

    Image pixels→Decision: 6
  5. 05

    Verifier

    Check the two answers on fresh scenes. After submission, the verifier runs held-out checks. A fixed answer mapping is applied separately to each program’s decision. Both answers must be valid and equal on every tested scene not excluded by a declared ambiguity rule.

    In this example

    Compare the answers from scene data and pixels. Repeat with fresh scenes, and check reproducibility and answer variation.

    Two computed answers→Agreement check

How the collection grows

A controller prepares each attempt and carries results forward. An episode is one fresh agent session followed by verification. A campaign repeats episodes with the same coding-agent configuration and generation instructions.

  1. 1

    Controller prepares inputs

    Instructions, three implementation demonstrations, accepted code, and the latest rejection report.

  2. 2

    Agent writes and tests

    The agent runs available self-checks, repairs failures, and finalizes one submission within its time limit.

  3. 3

    Verifier checks fresh scenes

    Held-out checks run after submission in a clean, offline container. The agent cannot inspect or repair against them.

  4. 4

    Controller updates the record

    A world is retained only after verification, proper finalization, and checks against direct reuse. Code or rejection reports inform the next episode.

↶ Repeat with a fresh coding-agent session

What does verification require?

Both programs must produce valid, matching answers on each tested scene that is not excluded. Checks also require reproducible generation and at least two answer classes for each question text. A fixed answer mapping is applied separately to each program’s decision.

An agent may declare an ambiguity rule: a deterministic rule that identifies scenes near a decision threshold. The verifier recomputes it and excludes those scenes from agreement testing. The current protocol does not cap the excluded fraction. Passing these checks establishes answer recovery on tested instances; it does not establish human clarity, novelty, or difficulty.

The three implementation demonstrations cover circle contact, angle acuteness, and counting with distractors. They are distinct from the generated examples selected below.

Programs behind the questions

3 · Model evaluation

Open-weight models struggle more than frontier models

A vision-language model (VLM) answers questions about images. Sol (high), Opus 5, and Gemini form the frontier panel; Gemma 4 12B, Gemma 4 31B, and Qwen 3.8 27B are evaluated separately as open-weight models.

Evaluators receive five fixed instances per world. Profile-conditioned evaluation covers 1,298 worlds; steered evaluation covers 874. The chart pools scored responses. Errors, refusals, and unparseable responses are accounted for separately.

Declared-transform questions were the hardest profile for each frontier evaluator. Different collection compositions prevent a causal comparison of difficulty.

4 · Model-feedback discovery

Model failures guide discovery of new challenging questions

Agents receive example worlds and frontier-model errors, then generate new worlds. A world is panel-hard when at least two frontier evaluators answer no more than three of five instances correctly, with all 15 responses present.

264worlds passed later replay
21 / 252complete-panel worlds were panel-hard
5worlds challenged all three frontier evaluators

All 21 panel-hard worlds passed replay. Verification remained independent of model predictions. Without a matched no-feedback control, the experiment demonstrates discovery under feedback but does not isolate its causal effect.

6 · Training and external transfer

Generated questions provide useful training supervision

Transfer to external benchmarks

The paper also reports four-split changes across 16 external benchmarks. The reported average across models and benchmarks is +2.2 points, with mixed outcomes across individual benchmarks. V* uses only jointly parseable responses in this summary, so its change is conditional on that subset.

VLMsAreBlind, PuzzleVQA, VLMsAreBiased, AlgoPuzzleVQA, PGM, and NaturalBench have positive mean changes for all three models. These benchmark averages are not pooled example-level accuracy.

What remains open

Agreement between two generated programs can preserve a shared mistake. Verification tests selected scenes and does not cap ambiguity-rule exclusions. Some accepted worlds fail later replay. Human review therefore remains a separate check of meaning and clarity.

Exact-reuse checks do not establish novelty. Steering and feedback experiments support descriptive findings without matched causal controls. Training gains vary by model and benchmark, and some additional split records and review decisions remain to be reconciled. These limits are part of how the results should be read.
