Method

The answer must be recoverable from the pixels.

BlindLoop asks a coding agent—a model that writes and tests code—to create a reusable visual question and two programs that answer it from different inputs.

One world, many instances

A question world contains a sampler, a renderer, fixed question text, and two answer programs. The sampler draws a scene description; the renderer turns it into an image. An instance is one sampled scene and its rendered image.

Two inputs, the same decision

The scene specification describes the objects and their relationships. The forward program answers from this specification. The inverse program answers from the image alone.

Reading the diagram

What each component does

The sampler and renderer create an instance. The forward and inverse programs answer the same question from different inputs. The verifier checks their agreement.

  1. 01

    Sampler

    Choose what to draw. The sampler uses a random seed to choose the objects and their properties. Its output is a scene specification: structured data describing one instance.

    In this example

    Choose six strings, their spacing, and the guitar’s position.

    Random seed→Scene specification
  2. 02

    Renderer

    Draw the chosen scene. The renderer turns the scene specification into an image. This makes the chosen properties visible as pixels.

    In this example

    Draw the guitar with six strings crossing a pale bridge.

    Scene specification→Image
  3. 03

    Forward program

    Answer using the scene data. The forward program computes the decision from the scene specification. Here that is a lookup; other questions may require geometry, connectivity, or simulation.

    In this example

    Read string_count = 6. No pixel measurements are needed.

    Scene specification→Decision: 6
  4. 04

    Inverse program

    Answer using only the image. The inverse program recovers the decision from visible pixels. It can know the world’s visual conventions, but does not receive this instance’s scene specification.

    In this example

    Locate the pale bridge, count six dark runs, and check that three neighboring rows agree.

    Image pixels→Decision: 6
  5. 05

    Verifier

    Check the two answers on fresh scenes. After submission, the verifier runs held-out checks. A fixed answer mapping is applied separately to each program’s decision. Both answers must be valid and equal on every tested scene not excluded by a declared ambiguity rule.

    In this example

    Compare the answers from scene data and pixels. Repeat with fresh scenes, and check reproducibility and answer variation.

    Two computed answers→Agreement check

How the collection grows

A controller prepares each attempt and carries results forward. An episode is one fresh agent session followed by verification. A campaign repeats episodes with the same coding-agent configuration and generation instructions.

  1. 1

    Controller prepares inputs

    Instructions, three implementation demonstrations, accepted code, and the latest rejection report.

  2. 2

    Agent writes and tests

    The agent runs available self-checks, repairs failures, and finalizes one submission within its time limit.

  3. 3

    Verifier checks fresh scenes

    Held-out checks run after submission in a clean, offline container. The agent cannot inspect or repair against them.

  4. 4

    Controller updates the record

    A world is retained only after verification, proper finalization, and checks against direct reuse. Code or rejection reports inform the next episode.

What does verification require?

Both programs must produce valid, matching answers on each tested scene that is not excluded. Checks also require reproducible generation and at least two answer classes for each question text. A fixed answer mapping is applied separately to each program’s decision.

An agent may declare an ambiguity rule: a deterministic rule that identifies scenes near a decision threshold. The verifier recomputes it and excludes those scenes from agreement testing. The current protocol does not cap the excluded fraction. Passing these checks establishes answer recovery on tested instances; it does not establish human clarity, novelty, or difficulty.

The three implementation demonstrations cover circle contact, angle acuteness, and counting with distractors. They are distinct from the generated examples selected below.

Testing the mechanism

What if the renderer shows the wrong answer?

Keep the intended scene and its forward answer fixed, but replace the image. If the inverse program responds to the pixels, an answer-changing replacement should expose a disagreement.

45 / 45 answer-changing substitutions were detected.

The test covered 15 worlds, with three trials per world. All original checks passed. Answers also agreed for all 45 answer-preserving substitutions and 45 lossless PNG re-encodings. Forward-only checks passed even on all answer-changing substitutions.

This controlled intervention measures sensitivity to rendering errors. It does not estimate how often such errors occur naturally.

Understanding the inverse programs

Different questions call for different computations

The paper studies 225 generated worlds, with five worlds from each coding-agent–profile pairing. A fresh analysis-agent session inspected each exported world without running its code.

From visible marks to a decision

An inverse program usually selects relevant pixels with color or brightness thresholds, groups them into objects or cells, and applies an explicit calculation. For example: measure a colored line, fit a circle through fragments, flood-fill rooms, match a transformed grid, or read arrows and update a counter. Each program is specialized for its world; expected palettes, layouts, and symbols can be fixed in code.

Source analysis and execution are separate

All 225 reviewed entry points accepted an image. Source analysis reported no scene-specification access or forward-code imports. A separate execution check in the paper covered the initial 90 worlds: all 270 stored-image answers matched their records.

Profile-conditioned discovery

Agents keep adding question worlds

A discovery profile gives a reasoning direction through instructions and five text-only example questions. The nine profiles cover tracing, topology, correspondence, search, state tracking, measurement, prior conflict, global structure, and declared transforms.

Five coding-agent configurations were run on all nine profiles: 45 campaigns, each with a six-hour budget and a 20-minute session cap. An episode-hour counts agent-session time, including provider waiting, but excludes later verification and analysis. A 200-scene replay is a later agreement check on fresh sampled scenes.

Image-support-steered discovery

Agents can follow requests about image regions

Some questions depend on a small object; others require a long path or several separated regions. This experiment requests one of nine size–shape combinations: focal, regional, or distributed extent, combined with compact, pathlike, or multipart shape.

Image support means the regions whose masking changes the inverse answer or causes an error. It measures the program’s sensitivity to masking, not human attention. The measured category does not determine acceptance.

Model evaluation

Frontier models solve most instances; open-weight models make more errors

A vision-language model (VLM) answers questions about images. The frontier panel here consists of Sol (high), Opus 5, and Gemini. Three open-weight models—Gemma 4 12B, Gemma 4 31B, and Qwen 3.8 27B—are evaluated separately.

Model-feedback discovery

Use model errors to guide the next questions

A world is panel-hard if at least two frontier evaluators answer no more than three of five instances correctly, with all 15 responses present. Of 1,547 complete-panel worlds from the earlier experiments, 70 met this criterion.

Two disjoint sets of ten such worlds supplied example implementations and evaluator feedback. Each coding-agent configuration ran on both sets for six hours per campaign. Later episodes received errors on new verified worlds. Verification stayed independent of model predictions. Open-weight models provided no feedback.

Human review

Program agreement is only one part of question quality

Two members of the author team independently reviewed the same 800 instances from all three discovery experiments. They answered the questions and recorded concerns about instructions, images, or recorded answers.

{{human}}

“Neither,” “one,” and “both” count reviewers whose concerns were classified as invalidity concerns. Under this classification, neither reviewer flagged 733 instances, one flagged 54, and both flagged 13. These are classified review outcomes, not adjudicated validity categories.

Classification and disagreement

The classification excludes 19 labels consisting of “confusing” from one reviewer’s profile-conditioned assessments. Restoring those labels gives 715 instances flagged by neither reviewer, 71 by one, and 14 by both. The final exclusion policy and disputed cases remain under review. The 95% complementary judgment proportion in the paper must not be read as a percentage of distinct items confirmed valid.

Training recipe

The main runs adapt attention and feed-forward projections in the language model; the vision tower is not directly adapted. LoRA uses rank 16, scaling 32, and dropout 0.05. Training uses one epoch, learning rate 0.0001, cosine decay, 3% warm-up, batch size two, and eight accumulation steps. The loss covers the answer and turn-end token. Qwen’s thinking mode is disabled.

What remains open

Agreement between two generated programs can preserve a shared mistake. Verification tests selected scenes and does not cap ambiguity-rule exclusions. Some accepted worlds fail later replay. Human review therefore remains a separate check of meaning and clarity.

Exact-reuse checks do not establish novelty. Steering and feedback experiments support descriptive findings without matched causal controls. Training gains vary by model and benchmark, and some additional split records and review decisions remain to be reconciled. These limits are part of how the results should be read.
